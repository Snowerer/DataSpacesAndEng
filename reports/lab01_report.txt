4. SYSTEM ARCHITECTURE DESCRIPTION:
The system is a simplified Orbital Observation Data Space (OODS)[cite: 6]. It consists of independent data providers (Satellite A, B, and Ground Station) [cite: 21, 22, 23, 24] and a federated metadata catalog[cite: 30]. Datasets remain stored at the provider nodes to maintain autonomy[cite: 8, 82].

5. ROLE OF THE METADATA CATALOG:
The catalog aggregates metadata from all providers to enable dataset discovery without centralizing the actual data[cite: 9, 10, 72]. It contains references (data_paths) that allow users to locate and access datasets stored elsewhere[cite: 85, 86, 112].

6. DISCUSSION QUESTIONS ANSWERS:
Q1: Which components store the actual data?
A1: The actual data is stored by the independent data providers (Satellite Provider A, Satellite Provider B, and Ground Station Provider)[cite: 8, 113, 117].
Q2: Which component enables dataset discovery?
A2: Dataset discovery is enabled by the federated metadata catalog[cite: 72, 111, 118].
Q3: What advantages does the federated architecture provide?
A3: It allows datasets to remain stored at independent providers [cite: 8], enables discovery without data centralization [cite: 10], and supports collaboration between multiple independent organizations[cite: 14, 119].
Q4: What limitations might such a system have?
A4: Potential limitations include the manual process of registering metadata [cite: 72, 120] and the lack of advanced query capabilities in this minimal version.
